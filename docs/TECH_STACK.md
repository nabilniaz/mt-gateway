# Tech stack rationale (Part 2)

The stack is small on purpose: seven runtime libraries, all widely used and actively maintained. Every choice favors fewer moving parts that are easy to explain in an interview.

| Area | Choice | Why | Rejected alternative | Trade-off accepted |
| --- | --- | --- | --- | --- |
| Language and tooling | Python 3.12, managed by **uv** (`pyproject.toml` + `uv.lock`) | uv installs Python 3.12 itself, resolves and locks dependencies in seconds, and gives identical installs on the Mac, in CI and in Docker | pip + venv (no lockfile, no Python install), Poetry (slower, doesn't manage Python) | uv is newer than pip, but widely adopted and backed by Astral (makers of ruff) |
| Web framework | **FastAPI** on **uvicorn** | Async from top to bottom, which a proxy needs: one process can hold hundreds of waiting upstream calls. Pydantic validation and OpenAPI docs at `/docs` for the admin API come free. | Flask (sync: each waiting upstream call blocks a worker), aiohttp (capable, but hand-written validation and no generated docs) | The proxy path uses a catch-all route and raw Starlette `Request`/`StreamingResponse`, slightly below FastAPI's usual style |
| Token scheme | **JWT, HS256, via PyJWT** | Standard claims give expiry (`exp`), identity (`sub`), audience and a unique id (`jti`) for free. Tokens verify with no database lookup. PyJWT is small and lets us pin the algorithm list. | HMAC-signed API key (you end up reinventing expiry, scopes and key ids), RS256/EdDSA (asymmetric is needed only when other parties verify; here the gateway both issues and verifies) | Symmetric key: any verifier could also mint tokens. Documented as a gap with a clear upgrade path. |
| Rate limiting | **Sliding-window counter**, in process memory | Matches the spec's "per-minute quota" exactly, uses two integers per tenant, and caps the boundary burst a fixed window allows | Fixed window (2x burst at :00), token bucket (models burst + refill rate, not "N per minute"), sliding log (one timestamp per request: memory grows with traffic), Redis (correct for many instances but adds a service to run) | Approximate (assumes the previous minute's requests were evenly spread) and single-instance |
| Route storage and runtime updates | **Immutable snapshot + copy-on-write**, writes serialized by an `asyncio.Lock`, seeded at startup from committed `config/routes.json` | Readers take no lock and can never see half an update. Writes are rare, so rebuilding the table on each write is cheap. Runtime changes stay in memory because App Platform's filesystem is wiped on every deploy; `GET /admin/routes/export` produces the seed-file format to commit. | Mutable dict with a lock around every read (all requests contend for one lock), a database or Managed Redis (more infrastructure than the task needs), writing changes to a local file (silently lost on App Platform) | Every write copies the whole table; runtime changes do not survive a restart until committed |
| HTTP proxying and timeouts | **httpx.AsyncClient**, one shared instance, `Timeout(connect=3, read=10, write=10, pool=2)`, `Limits(max_connections=100)`, `follow_redirects=False` | Connection pooling and keep-alive across requests; separate timeouts let a slow connect fail fast; streams bodies; its built-in `MockTransport` and `ASGITransport` make it testable without a network | aiohttp client (fine, but a second HTTP stack and a different mocking story), `requests` (sync) | httpx is a little slower than aiohttp under heavy load; irrelevant at this scale |
| Validation and config | **pydantic v2** models, **pydantic-settings** for env vars | One declaration validates admin bodies, config files and environment variables, with clear 422 errors | Hand-written checks (easy to miss a case) | Small learning curve on pydantic's v2 syntax |
| Structured logging | **structlog**, JSON renderer to stdout | Each audit line is a dict rendered as JSON, so escaping (and log-injection defense) is automatic; context such as `request_id` binds once per request | Standard `logging` + a JSON formatter (works, but more boilerplate for per-request context) | One more dependency |
| Testing | **pytest**, **pytest-asyncio**, **pytest-cov**, httpx's `ASGITransport`/`MockTransport`, plus the real demo upstream app in-process | Unit tests for auth, policy, path normalization, rate limiter, breaker and canary use plain functions with an injectable clock. Integration tests run the full gateway against a real FastAPI upstream through httpx's ASGI transport, so no ports or network are needed. `MockTransport` raises timeouts and connection errors for 502/504. | unittest (more ceremony, weaker fixtures), respx (an extra dependency for what `MockTransport` already does), Docker-only integration tests (slow; used just for the CI smoke test) | ASGI transport skips real sockets, so `scripts/smoke.sh` also hits the real Docker stack in CI |
| Lint and types | **ruff** (lint + format), **mypy** strict | Catches mistakes before tests run; ruff replaces flake8, isort and black in one fast tool | flake8 + black + isort (three tools, slower) | Strict typing takes some annotation effort |
| CI | **GitHub Actions**: `astral-sh/setup-uv`, then ruff, mypy, pytest with coverage, then `docker build` | Runs the whole suite on every push and pull request, as the spec requires; also proves the image builds | GitLab CI, CircleCI (would need another account) | Linux-only runners; macOS is covered by local runs |
| Containerization | **Multi-stage Dockerfile** on `python:3.12-slim`, non-root user, `HEALTHCHECK` on `/healthz`; `docker-compose.yml` runs gateway + demo upstream locally | Small image, no build tools in the final layer, and the exact same image runs locally and on DigitalOcean | Alpine (musl breaks prebuilt wheels and slows builds), distroless (harder to debug for a learning project) | Slim is larger than distroless |
| Deployment | **DigitalOcean App Platform** from the GitHub repo, defined in `.do/app.yaml` | Builds the Dockerfile, provides HTTPS and certificates, health-checked zero-downtime deploys, encrypted secrets and log viewing, with no server to patch | Droplet + Docker (you must set up TLS, a reverse proxy, OS updates, restarts and deploy scripts yourself), DigitalOcean Kubernetes (far more than one service needs) | Less control over the host; more expensive per unit of CPU than a Droplet; must stay at 1 instance until state moves to Redis |

**Runtime dependencies:** `fastapi`, `uvicorn[standard]`, `httpx`, `pyjwt`, `pydantic`, `pydantic-settings`, `structlog`.

**Dev dependencies:** `pytest`, `pytest-asyncio`, `pytest-cov`, `ruff`, `mypy`.
